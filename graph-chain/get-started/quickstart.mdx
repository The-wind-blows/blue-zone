## 构建基础agent

首先创建一个可以回答问题和调用工具的简单agent。本例中的agent使用所选的语言模型、一个基本的天气函数作为工具(tool)，以及一个简单的提示词(prompt)来指导其行为：

```python
from langchain.agents import create_agent

def get_weather(city: str) -> str:
    """Get weather for a given city."""
    return f"It's always sunny in {city}!"

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[get_weather],
    system_prompt="You are a helpful assistant",
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "What's the weather in San Francisco?"}]}
)
print(result["messages"][-1].content_blocks)
```

当你运行代码并提示agent告诉你旧金山的天气时，agent将使用该输入及其可用上下文。agent了解你正在询问旧金山市的天气，因此使用所提供的城市名称呼叫天气工具(tool)。

:::tip[ ]
<small>
你可以通过更改模型名称并设置适当的API键来使用任何受支持的模型。与LangSmith一起追踪你的agent内部发生了什么。按照tracing quickstart进行设置。

我们还建议你设置LangSmith引擎，该引擎可以监视你的跟踪、检测问题并提出修复方案。
</small>
:::

## 构建一个真实世界的agent

在以下示例中，你将构建一个可以回答有关文本文件问题的研究agent。在此过程中，你将探索以下概念：
1. 详细的system prompts，以改善agent行为
2. 创建与外部数据集成的tool
3. 用于一致响应的模型配置
4. 聊天式互动的会话记忆
5. 用于内置功能的Deep agent
6. 测试你的agent

### 定义system prompt

系统提示词定义了agent的角色和行为。保持其具体性和可操作性：
```python
SYSTEM_PROMPT = """You are a literary data assistant.

## Capabilities

- `fetch_text_from_url`: loads document text from a URL into the conversation.
Do not guess line counts or positions—ground them in tool results from the saved file."""
```

### 创建tools

tool允许模型通过调用你定义的函数与外部系统进行交互。tool可以依赖于运行时上下文，也可以与agent内存交互。
此示例使用一个tool从给定的URL加载文档：
```python
import urllib.error
import urllib.request
from langchain.tools import tool

@tool
def fetch_text_from_url(url: str) -> str:
    """Fetch the document from a URL.
    """
    req = urllib.request.Request(
        url,
        headers={"User-Agent": "Mozilla/5.0 (compatible; quickstart-research/1.0)"},
    )
    try:
        with urllib.request.urlopen(req, timeout=120) as resp:
            raw = resp.read()
    except urllib.error.URLError as e:
        return f"Fetch failed: {e}"
    text = raw.decode("utf-8", errors="replace")
    return text
```

:::tip[ ]
<small>
tool应该有很好的文档记录：它们的名称、描述和参数名称成为模型提示词的一部分。LangChain的@tool装饰器添加元数据，并使用ToolRuntime参数启用运行时注入。在工具指南中了解更多信息。
</small>
:::

### 配置模型

为你的用例设置具有正确参数的语言模型。例如：
```python
from langchain.chat_models import init_chat_model

model = init_chat_model(
    "openai:gpt-5.5",
    temperature=0.5,
    timeout=300,
    max_tokens=25000,
)
```
根据所选的模型和提供者，初始化参数可能会有所不同；详情请参阅他们的参考页面。

### 添加记忆

为agent添加内存，以在交互中保持state。这允许state记住之前的对话和上下文。
```python
from langgraph.checkpoint.memory import InMemorySaver
checkpointer = InMemorySaver()
```
:::tip[ ]
<small>
在生产环境中，使用持久化checkpointer将消息历史记录保存到数据库中。有关更多详细信息，请参阅添加和管理内存。
</small>
:::

### 创建和运行agent

现在，使用所有组件组装你的agent并运行它。

创建agent有两种不同的框架：LangChain agent和deep agent。LangChain和deep agent都为你提供了对工具、内存等的细粒度控制。
两者之间的主要区别在于，deep agent已经内置了一系列常用的功能，如规划、文件系统工具和subagent。

当你希望以最少的设置获得最大的功能时，请使用deep agent；当你需要精细控制时，请选择LangChain agent。

要在此步骤中比较两者，请安装deepagents软件包：

    ```python

    ```
  </TabItem>
  <TabItem value="uv" label="uv">
    ```python

    ```
  </TabItem>
</Tabs>

:::warning
<small>
此示例将《了不起的盖茨比》的全文发送给模型，可能需要一两分钟的时间才能回复。你可以在下一步中查看示例输出。
</small>
:::

另一方面，deep agent可以：

对于LangChain agent，你必须实现更多功能以获得类似的服务级别，并可以根据需要进行自定义。



## 跟踪agent调用

你用LangChain构建的最有趣的agent会给LLM打很多电话。随着这些agent变得越来越复杂，能够检查agent内部到底发生了什么变得非常重要。最好的办法就是和LangSmith一起。

注册LangSmith帐户并设置以下内容以开始记录跟踪：
```python
export LANGSMITH_AGENT_ID="<your-agent-id>"
export LANGSMITH_AGENT_ENVIRONMENT="local"
export LANGSMITH_TRACING="true"
export LANGSMITH_API_KEY="..."
```

设置后，再次运行脚本，然后检查你的agent在LangSmith通话期间发生了什么。
