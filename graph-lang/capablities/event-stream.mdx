# 事件流

对于大多数LangGraph应用程序代码，事件流是推荐的进程内流模型。它返回一个可以同时以多种方式使用的运行流对象。

## 快速入门
```python
stream = graph.stream_events({
    "messages": [{"role": "user", "content": "What is 42 * 17?"}],
}, version="v3")

for message in stream.messages:
    for token in message.text:
        print(token, end="", flush=True)

final_state = stream.output
```
要根据agent服务器后面部署的图形进行流式传输，请参阅LangSmith Streaming API。

## 碎片如何组合在一起
流堆栈有两个主要层：
1. 流媒体从Pregel引擎发出原始图形执行事件。
2. 事件流将这些事件规范化，通过流转换器运行它们，并公开类型化的投影。

<center><ZoomImage src={eventStream} alt=''/></center>

事件路由器是两层之间的桥梁。它接收标准化的Pregel事件，并将每个事件传递给注册的流转换器。
内置转换器创建标准投影，如`stream.messages`、`stream.values`、`stream.subgraph`和`stream.output`。
自定义转换器可以在`stream.extensions`下添加特定于应用程序的投影。

## 事件流提供了什么
运行流在一个底层事件流上公开类型化的投影：
| Projection | Use |
|---|---|
| stream            |  迭代每个协议事件。                |
| stream.messages   |  流式聊天模型messages和token增量。  |
| stream.values     |  迭代状态快照并等待最终值。         |
| stream.output     |  等待最终输出。                    |
| stream.subgraphs  |  发现并观察嵌套图的执行。           |
| stream.interrupts |  检查human-in-the-loop中断有效载荷。|
| stream.interrupted|  检查运行是否因人工输入而暂停。      |
| stream.extensions |  使用自定义流转换器投影。            |


多个消费者可以同时阅读这些预测。读取`stream.messages`不会消耗`stream.values`、`stream.subgraphs`或`stream.output`所需的事件。

事件流位于流之上一级，它通过stream_mode模式(如updates, values, messages, custom, checkpoints, tasks, 和 debug)公开原始图执行事件。
当你需要对这些模式进行底层访问时，请使用流媒体；当应用程序代码从类型化投影中受益时，使用事件流。

## 流式传输消息
使用`stream.messages`进行聊天模型输出：
```python
stream = graph.stream_events(input, version="v3")

for message in stream.messages:
    text = str(message.text)
    usage = message.output.usage_metadata

    print(text)
    print(usage)
```
message.text在同步代码中是可迭代的。逐个标记输出迭代它，或调用str(message.text)获取完整文本。

message.reasoning暴露了推理的差异。message.toolcalls公开了工具调用块。每个块都包含调用的id、名称，并且只包含其args的新部分。
如果你需要文本、推理和工具调用块以精确的到达顺序，请迭代消息流的原始事件，而不是分别进行每个投影。

## 流式子图
使用stream.subgraphs观察嵌套图的工作，而无需解析命名空间字符串：
```python
stream = graph.stream_events(input, version="v3")

for subgraph in stream.subgraphs:
    print(subgraph.graph_name, subgraph.path)

    for message in subgraph.messages:
        print(message.text)
```

subgraph.graph_name是编译的图或agent的名称。从工具分派的命名agent(例如，通过Deep Agents任务工具调用的create_agent（name=…）)在该名称下出现，
打开作用域的生命周期事件携带了一个推理，该推理链接回分派工具调用。有关更多信息，请参阅生命周期。

对于特定于产品的流，请参阅subagent流的deep agent流和工具调用和中间件事件的LangChain agent流。

## 流状态
使用`stream.values`在每个步骤后流式传输完整状态快照：
```python
stream = graph.stream_events(input, version="v3")

for snapshot in stream.values:
    print(snapshot)

final_state = stream.output
```
## 流式传输多个投影
对于异步代码中的并发消费，使用`astream_events`和`asyncio.gather`：
```python
import asyncio

stream = await graph.astream_events(input, version="v3")

async def consume_messages():
    async for message in stream.messages:
        print(f"[llm] node={message.node}")

async def consume_subgraphs():
    async for subgraph in stream.subgraphs:
        print(f"[subgraph] path={subgraph.path}")

await asyncio.gather(consume_messages(), consume_subgraphs())
```

对于同步代码，使用stream.sincterate(…)以严格的到达顺序消耗多个投影：
```python
stream = graph.stream_events(input, version="v3")

for name, item in stream.interleave("values", "messages", "subgraphs"):
    if name == "values":
        print(f"[state] keys={list(item)}")
    elif name == "messages":
        print(f"[llm] node={item.node}")
    elif name == "subgraphs":
        print(f"[subgraph] path={item.path}")
```

## 中断后继续
当图因人工输入而暂停时，检查`stream.interrupted`和`stream.ininterrupts`，然后使用Command再次调用stream_events（…，version=“v3”）来恢复。

Resume需要一个使用checkpointer和带有线程ID的配置编译的图——请参阅持久化。
```python
from langgraph.types import Command

stream = graph.stream_events(input, version="v3")

for message in stream.messages:
    print(message.text)

if stream.interrupted:
    print(stream.interrupts)

stream = graph.stream_events(
    Command(resume={"decisions": [{"type": "approve"}]}),
    version="v3",
)
final_state = stream.output
```

## 流式传输所有协议事件
当你需要原始协议事件流时，请使用run对象本身：
```python
stream = graph.stream_events({
    "messages": [{"role": "user", "content": "What is 42 * 17?"}],
}, version="v3")

for event in stream:
    namespace = event["params"]["namespace"]
    print(namespace, event["method"], event["params"]["data"])
```

每个事件都是一个ProtocolEvent信封，包裹着特定于通道的有效载荷。transformer的过程（事件）接收到的形状相同。
```python
class ProtocolEvent(TypedDict):
    seq: int                    # strictly increasing within a run; use for ordering
    method: str                 # channel name: "messages", "values", "updates", "custom", "tools", "lifecycle", ...
    params: ProtocolEventParams


class ProtocolEventParams(TypedDict):
    namespace: list[str]        # path of "<name>:<runtime_id>" segments from the root graph; [] is the root
    timestamp: int              # wall-clock milliseconds; can drift, don't rely on for ordering
    data: Any                   # channel-specific payload; shape depends on `method`
```

命名空间是从根图到发出事件的作用域的路径。根是空数组[]。每个子执行都会添加一个“name:runtime_id”段，
因此子图内的嵌套工具调用看起来像[“researcher:6f4d”，“tools:91ac”]。前面的名称：是稳定图或节点名称；后缀是每次调用的运行时ID。
当你只关心特定的子树时，你可以自己按名称空间过滤原始事件——stream.subgraphs已经对嵌套图执行这样做了。

## 通道和事件生命周期
原始事件在通道上流动。通道名称显示为事件的方法；每个通道发出特定的事件shape。
| Channel  | Purpose  |
|---|---|
| values      |  完整的图状态快照               |
| updates     |  每个节点的状态增量    |
| messages    |  以内容块为中心的聊天模型输出。   |
| tools       |  工具调用开始、流式输出、完成和错误事件。   |
| lifecycle   |  运行、子图和subagent状态更改。            |
| checkpoints |  用于分支和时间旅行的轻量级checkpoint信封。 |
| input       |  Human-in-the-loop 中输入请求和响应。      |
| tasks       |  Pregel任务创建和结果事件          |
| custom      |  来自图代码的用户定义有效载荷。     |
| custom:\< name \>            |   应用程序定义的流转换器输出。         |

类型化的投影(stream.messages、stream.values等)是从这些通道构建的。当你直接迭代run对象时，通道名称在原始事件上显示为方法字段。

### 消息
消息通道模型以内容块的形式输出。数据的事件字段是以下字段之一：
- message-start
- content-block-start
- content-block-delta
- content-block-finish
- message-finish

内容块有明确的边界：块开始，发出零个或多个增量，并在同一消息中的下一个块开始之前完成。这使得token流、推理块、工具调用块和多模式内容变得明确，
而不需要特定于提供商的格式。`message-finish`可能包括token使用；不可恢复的模型调用失败以消息错误事件的形式出现。

每个`content-block-delta`事件在其索引处为块携带一个增量：
| Delta type  | Effect on the block  |
|---|---|
| text-delta          |  将其text附加到块的text中。    |
| reasoning-delta     |  将其reasoning附加到块的reasoning中。    |
| data-delta          |  将其data附加到块的data64中。    |
| tool-call-delta     |  将其args附加到块的args中。      |
| block-delta         |  在块上的字段中设置每个键，替换之前的值。  |

`content-block-finish`携带完整块。忽略任何您无法识别的增量类型，并继续读取流。

要直接使用原始内容块事件，而不是使用stream.messages投影：
```python
for event in stream:
    if event["method"] != "messages":
        continue

    data = event["params"]["data"][0]
    if not isinstance(data, dict):
        continue
    if data.get("event") != "content-block-delta":
        continue

    block = data.get("delta") or {}
    if block.get("type") == "text-delta":
        print(block.get("text", ""), end="", flush=True)
    elif block.get("type") == "reasoning-delta":
        print(f"[thinking]{block.get('reasoning', '')}", end="", flush=True)
    elif block.get("type") == "tool-call-delta":
        print(f"[args]{block.get('args', '')}", end="", flush=True)
```


### 工具
工具通道公开工具执行。数据的事件字段是以下字段之一：
- tool-started
- tool-output-delta
- tool-finished
- tool-error

工具事件通过工具调用ID进行关联，因此工具执行可以在消息通道上连接回其原始工具调用内容块。

### 生命周期
生命周期通道跟踪根运行、子图和subagent状态。数据的事件字段是以下字段之一：
- started
- running
- completed
- failed
- interrupted

除了事件之外，生命周期数据可能还包括一个可选的graph_name、error和 cause 描述子作用域启动原因(父工具调用、扇出发送、边缘转换)。

## 构建自己的投影

流转换器是事件流中的投影层。它们观察协议事件，保持自己的状态，并公开运行的派生视图，如工具活动、token总计、进度事件、工件或另一个协议的消息。
StreamChannel是用于发布这些视图的投影图元转换器。

内置的预测(stream.messages、stream.values、stream.subgraphs、streams.out)和特定于产品的预测(LangChain的stream.tool_calls、Deep Agents的stream.ssubgents)本身就是使用相同合约的转换器。
用户转换器通过编译时或调用时注册堆叠在顶部，它们的投影显示在stream.extensions下。

当现有的投影与应用程序所需的形状不匹配时，编写一个。

### transformers的工作原理
事件流从LangGraph Pregel引擎的流式输出开始。运行时将这些块标准化为协议事件，然后流处理程序通过一堆流转换器路由每个事件。
<center><ZoomImage src={transFormer} alt=''/></center>

流处理程序是一个流的中央调度器。对于每个协议事件，它：
1. 按顺序调用每个已注册的转换器的进程（事件）挂钩。
2. 名为StreamChannel的线路将推回到协议事件流上。
3. 将事件存储在运行流中，除非变压器抑制它。
4. 运行结束时，在每个transformer上调用finalize（）或fail（）。

Transformers是观察性的。它们不会回调到图运行时。相反，它们使用事件并将派生值推送到StreamChannel、promise或其他投影对象中。

### Transformer shape
Transformer实现`StreamTransformer`接口：
```python
from langgraph.stream import ProtocolEvent, StreamTransformer


class MyTransformer(StreamTransformer):
    def init(self) -> dict:
        ...

    def process(self, event: ProtocolEvent) -> bool:
        ...

    def finalize(self) -> None:
        ...

    def fail(self, err: BaseException) -> None:
        ...
```

- init（）创建投影对象。用户变压器投影显示在stream.extensions下。
- process（）观察每个协议事件。有关ProtocolEvent形状，请参阅流式传输所有协议事件。仅当你有意抑制原始事件时，才返回false。
- finalize（）在流成功后关闭或解析非通道投影。
- fail（）将错误传播到非通道投影。

### 声明所需的流模式

required_stream_modes控制底层图在流期间发出的Pregel流模式。运行时获取每个已注册transformer的required_stream_mode的并集，并将该并集作为stream_mde参数传递给图的.stream（）调用。
从不发出transformer请求的模式——声明（“自定义”）是导致自定义事件在运行中流动的原因。
```python
class CustomTransformer(StreamTransformer):
    required_stream_modes = ("custom",)

    def process(self, event: ProtocolEvent) -> bool:
        if event["method"] == "custom":
            ...
        return True
```
process（）接收图发出的每个事件，并负责按事件[“方法”]进行过滤。申报开启上游排放；它不会缩小process（）看到的范围。
有效值是Pregel流模式："messages", "tools", "custom", "values", "updates", "checkpoints", "tasks", "debug。
每个tramsformer都必须声明它所作用的每个模式——省略的模式不会由图发出，也永远不会到达process（）。

### StreamChannel
StreamChannel是转换器用于流式传输值的投影图元。它总是公开一个可迭代的流。stream.extensions. < name > .
构造函数参数决定每个push（）是否也作为 custom: < name > 事件流入运行的主事件流：< name >事件——也就是说，在迭代原始协议事件时是否显示投影的值。
| Need  | Use  |
|---|---|
| 仅侧通道投影                 |  StreamChannel()       |
| 还将每个推送流到主事件流中    |  StreamChannel(name)    |

命名通道有效载荷必须是可序列化的，因为每个推送的值也会成为主流中的custom：< name > 协议事件。在未命名通道中保留promise、异步可迭代对象、类实例和其他进程内句柄。

流处理程序拥有通道生命周期。一旦init（）返回一个通道，处理程序就会在运行结束时为你关闭或失败。transformer只推送值。

### 示例：命名通道
将字符串名称传递给StreamChannel，以通过stream.extensions公开流式投影，并将每个推送的值作为custom: < name > 协议事件转发到运行的主事件流中：
```python
from typing import TypedDict

from langgraph.stream import ProtocolEvent, StreamChannel, StreamTransformer


class ToolActivity(TypedDict):
    name: str
    status: str


class ToolActivityTransformer(StreamTransformer):
    required_stream_modes = ("tools",)

    def __init__(self, scope: tuple[str, ...] = ()) -> None:
        super().__init__(scope)
        self.activity = StreamChannel[ToolActivity]("tool_activity")

    def init(self) -> dict:
        return {"tool_activity": self.activity}

    def process(self, event: ProtocolEvent) -> bool:
        if event["method"] != "tools":
            return True

        data = event["params"]["data"]
        if isinstance(data, dict) and data.get("tool_name") and data.get("event"):
            status = "error" if data["event"] == "tool-error" else "started"
            self.activity.push({"name": data["tool_name"], "status": status})
        return True
```

### 示例：未命名频道
如果没有名称，该通道只是一个侧通道投影——可以在stream.extensions上访问，但迭代原始事件的消费者看不到。
对于持有无法序列化到主事件流上的进程内句柄（promise、异步可迭代对象、类实例）的投影来说，这是正确的选择。

下面的示例将一个未命名的通道与get_stream_writer配对，这允许图节点发出自定义通道事件，然后transformer将这些事件排入投影：
```python
from langgraph.config import get_stream_writer
from langgraph.stream import ProtocolEvent, StreamChannel, StreamTransformer


def node(state):
    writer = get_stream_writer()
    writer({"kind": "progress", "message": "retrieving context"})
    return state


class CustomTransformer(StreamTransformer):
    required_stream_modes = ("custom",)

    def __init__(self, scope: tuple[str, ...] = ()) -> None:
        super().__init__(scope)
        self.log = StreamChannel()

    def init(self) -> dict:
        return {"custom": self.log}

    def process(self, event: ProtocolEvent) -> bool:
        if event["method"] == "custom":
            self.log.push(event["params"]["data"])
        return True


stream = graph.stream_events(input, version="v3", transformers=[CustomTransformer])

for item in stream.extensions["custom"]:
    print(item)
```

### 示例：final-value projection

当投影不应流入主事件流时，使用未命名流、promise或其他进程内对象：
```python
from langgraph.stream import ProtocolEvent, StreamChannel, StreamTransformer


class StatsTransformer(StreamTransformer):
    required_stream_modes = ("messages",)

    def __init__(self, scope: tuple[str, ...] = ()) -> None:
        super().__init__(scope)
        self.total_tokens = 0
        self.total_tokens_log = StreamChannel[int]()

    def init(self) -> dict:
        return {"total_tokens": self.total_tokens_log}

    def process(self, event: ProtocolEvent) -> bool:
        data = event["params"]["data"]
        if isinstance(data, dict):
            usage = data.get("usage") or {}
            self.total_tokens += usage.get("output_tokens") or 0
        return True

    def finalize(self) -> None:
        self.total_tokens_log.push(self.total_tokens)
        self.total_tokens_log.close()
```

### 在调用时或编译时注册

在呼叫时间通过transformer进行本地实验：
```python
stream = graph.stream_events(
    input,
    version="v3",
    transformers=[StatsTransformer, ToolActivityTransformer],
)
```
当该图的每次运行都应产生投影时，将transformer编译到该图中：
```python
graph = builder.compile(
    transformers=[StatsTransformer, ToolActivityTransformer],
)
```

### 内置: ToolCallTransformer
LangGraph内置`ToolCallTransformer`。注册它以在普通`StateGraph`上公开`stream.tool_calls`：
```python
from langgraph.prebuilt import ToolCallTransformer

stream = graph.stream_events(input, version="v3", transformers=[ToolCallTransformer])

for tool_call in stream.tool_calls:
    print(tool_call.tool_name, tool_call.input)
```

## 相关
LangGraph定义了流式图元。要使用LangChain或Deep Agents的流媒体，请查看相关产品文档：
- LangChain agent流包括ReAct风格的agent消息、工具调用和中间件更新。
- Deep Agents流包括subagent、嵌套消息和subagent工具调用。
- LangChain前端模式和LangGraph前端模式显示了基于流式状态构建的UI用例。
- LangSmith Streaming API涵盖了针对部署在agent服务器后面的图形的流式传输。

线级事件和命令格式在Agent Protocol存储库中定义，在PyPI上可作为langchain-protocol使用，在npm上可作为@langchain/Protocol使用。
