# Stores
store使agent能够跨线程持久化信息，包括用户偏好、积累的知识以及应在单个对话后继续存在的事实。与将整个图状态保存在一个线程范围内的checkpointer不同，store保存了可从任何线程访问的任意键值数据。
<center><ZoomImage src={myImg} alt=''/></center>

:::info
<small>
使用agent服务器时agent服务器自动处理存储，你不需要手动实现或配置存储。API在后台为你处理所有存储基础架构。
</small>
:::

:::info
<small>
InMemoryStore适用于开发和测试。对于生产，请使用PostgresStore、MongoDBStore、Rediscostore或UptashStore等持久存储。所有实现都扩展了BaseStore，BaseStore是节点函数签名中使用的类型注释。
</small>
:::

:::info
<small>
有关可用提供商的完整列表，请参阅store集成
</small>
:::

## 基础用法

以下代码片段单独显示了InMemoryStore，而没有使用LangGraph：
```python
from langgraph.store.memory import InMemoryStore
store = InMemoryStore()
```
memories由元组命名，在下面的示例中为(< user_id >，“Memories”)。名称空间可以是任何长度，表示任何内容，不必是特定于用户的。
```python
user_id = "1"
namespace_for_memory = (user_id, "memories")
```
使用store.put方法将记忆保存到store中的命名空间。如上所述，指定命名空间和内存的键值对：键只是内存的唯一标识符(memory_id)，值(字典)是记忆本身。
```python
memory_id = str(uuid7())
memory = {"food_preference" : "I like pizza"}
store.put(namespace_for_memory, memory_id, memory)
```
使用store.search方法从命名空间中读取记忆，该方法以列表形式返回给定用户的记忆，最大参数为limit(默认值10)。使用InMemoryStore，项目按插入顺序返回，因此最近的记忆在列表中的最后一个；
其他后端可能会对记忆进行不同的排序(请参阅在名称空间中列出项目)。
```python
memories = store.search(namespace_for_memory)
memories[-1].dict()
{'value': {'food_preference': 'I like pizza'},
 'key': '07e0caf4-1631-47b7-b15f-65515d4c1843',
 'namespace': ['1', 'memories'],
 'created_at': '2024-10-02T17:22:31.590602+00:00',
 'updated_at': '2024-10-02T17:22:31.590605+00:00'}
```
每种记忆类型都是一个具有特定属性的Python类(Item)。我们可以通过用.dict转换将其作为字典访问.

它具有以下属性：
- value：这个记忆的值(本身就是一个字典)
- key：此命名空间中此内存的唯一键
- namespace：字符串元组，此记忆类型的命名空间
:::info
<small>
虽然类型是tuple[str，…]，但当转换为JSON时，它可能会被序列化为列表(例如，['1'，'memories'])。
</small>
:::
- created_at：创建此记忆的时间戳
- updated_at：此记忆更新的时间戳

## 在命名空间中列出项目

在没有查询和过滤器的情况下调用`store.search`(或异步`store.asearch`)，最多返回存储在`namespace_prefix`下的项。当你不需要语义排名时，使用此选项枚举名称空间中的所有内容。
```python
# Return up to 100 items stored under ("alice", "memories").
items = store.search(("alice", "memories"), limit=100)
```
要记住三个行为：
- `namespace_prefix`按前缀匹配，但不完全精确。(“alice”，)还返回(“alices”，“memories”)，(“alize”，“preferences”)等下的项目。要限制到单个级别，请在item.namespace上传递完整的命名空间或在客户端过滤返回的项目。
- 超出限制的结果将被自动截断。没有溢出信号——将限制设置为高于预期的最大值，或用偏移量分页。
- 默认订购取决于store后端。`PostgresStore`和`AsyncPostgresStore`返回的结果按updated_at降序排列(最近更新的结果排在第一位)。InMemoryStore按插入顺序返回结果(最近插入的最后一个)。
  不要依赖于实现之间的特定顺序；如果顺序很重要，请在item.updated-at上对客户端进行排序。

要遍历大型命名空间，请执行以下操作：
```python
page_size = 50
offset = 0
while True:
    page = store.search(("alice", "memories"), limit=page_size, offset=offset)
    if not page:
        break
    for item in page:
        pass
    offset += page_size
```

要发现存在哪些命名空间(例如，在列出每个用户的记忆之前对其进行迭代)，请使用`store.list_namespaces`或`store.alist_namespace`:
```python
# All namespaces that start with ("alice",), truncated to two levels deep.
namespaces = store.list_namespaces(prefix=("alice",), max_depth=2)
```
## 语义搜索
除了简单的检索，该store还支持语义搜索，允许你根据语义而不是精确匹配来查找记忆。要启用此功能，请使用嵌入模型配置存储：
```python
from langchain.embeddings import init_embeddings

store = InMemoryStore(
    index={
        "embed": init_embeddings("openai:text-embedding-3-small"),  # Embedding provider
        "dims": 1536,                              # Embedding dimensions
        "fields": ["food_preference", "$"]              # Fields to embed
    }
)
```
现在，在搜索时，你可以使用自然语言查询来查找相关记忆：
```python
# Find memories about food preferences
# (This can be done after putting memories into the store)
memories = store.search(
    namespace_for_memory,
    query="What does the user like to eat?",
    limit=3  # Return top 3 matches
)
```

你可以通过配置fields参数或在存储记忆时指定index参数来控制记忆的哪些部分被嵌入：
```python
# Store with specific fields to embed
store.put(
    namespace_for_memory,
    str(uuid7()),
    {
        "food_preference": "I love Italian cuisine",
        "context": "Discussing dinner plans"
    },
    index=["food_preference"]  # Only embed "food_preferences" field
)

# Store without embedding (still retrievable, but not searchable)
store.put(
    namespace_for_memory,
    str(uuid7()),
    {"system_info": "Last updated: 2024-01-01"},
    index=False
)
```

## 在LangGraph中使用
该存储与checkpointer协同工作：如上所述，checkpointer将状态保存到线程，该存储允许你存储任意信息以供跨线程访问。使用checkpointer和存储编译图，如下所示。
```python
from dataclasses import dataclass
from langgraph.checkpoint.memory import InMemorySaver

@dataclass
class Context:
    user_id: str

# We need this because we want to enable threads (conversations)
checkpointer = InMemorySaver()

# ... Define the graph ...

# Compile the graph with the checkpointer and store
builder = StateGraph(MessagesState, context_schema=Context)
# ... add nodes and edges ...
graph = builder.compile(checkpointer=checkpointer, store=store)
```

然后，如前所述，使用thread_id调用图，并使用user_id调用图, 它像以前一样用作该特定用户的存储器的命名空间。
```python
# Invoke the graph
config = {"configurable": {"thread_id": "1"}}

# First let's just say hi to the AI
for update in graph.stream(
    {"messages": [{"role": "user", "content": "hi"}]},
    config,
    stream_mode="updates",
    context=Context(user_id="1"),
):
    print(update)
```

你可以使用Runtime对象从任何节点访问存储和user_id。当你将运行时作为参数添加到节点函数中时，LangGraph会自动注入运行时。你可以用它来保存记忆：
```python
from langgraph.runtime import Runtime
from dataclasses import dataclass

@dataclass
class Context:
    user_id: str

async def update_memory(state: MessagesState, runtime: Runtime[Context]):

    # Get the user id from the runtime context
    user_id = runtime.context.user_id

    # Namespace the memory
    namespace = (user_id, "memories")

    # ... Analyze conversation and create a new memory

    # Create a new memory ID
    memory_id = str(uuid7())

    # We create a new memory
    await runtime.store.aput(namespace, memory_id, {"memory": memory})
```
你还可以从任何节点访问存储，并使用`store.search`方法获取记忆。记忆以可以转换为字典的对象列表的形式返回。
```python
memories[-1].dict()
{'value': {'food_preference': 'I like pizza'},
 'key': '07e0caf4-1631-47b7-b15f-65515d4c1843',
 'namespace': ['1', 'memories'],
 'created_at': '2024-10-02T17:22:31.590602+00:00',
 'updated_at': '2024-10-02T17:22:31.590605+00:00'}
```

你可以访问记忆并在模型调用中使用它们。
```python
from dataclasses import dataclass
from langgraph.runtime import Runtime

@dataclass
class Context:
    user_id: str

async def call_model(state: MessagesState, runtime: Runtime[Context]):
    # Get the user id from the runtime context
    user_id = runtime.context.user_id

    # Namespace the memory
    namespace = (user_id, "memories")

    # Search based on the most recent message
    memories = await runtime.store.asearch(
        namespace,
        query=state["messages"][-1].content,
        limit=3
    )
    info = "\n".join([d.value["memory"] for d in memories])

    # ... Use memories in the model call
```

如果你创建了一个新线程，只要`user_id`相同，你仍然可以访问相同的记忆。
```python
# Invoke the graph on a new thread
config = {"configurable": {"thread_id": "2"}}

# Let's say hi again
for update in graph.stream(
    {"messages": [{"role": "user", "content": "hi, tell me about my memories"}]},
    config,
    stream_mode="updates",
    context=Context(user_id="1"),
):
    print(update)
```

当你在本地(例如在Studio中)或托管中使用LangSmith时，默认情况下可以使用基本存储，你不需要在图编译期间指定它。但是，要启用语义搜索，你确实需要在langgraph.json文件中配置索引设置。例如：
```python
{
    ...
    "store": {
        "index": {
            "embed": "openai:text-embeddings-3-small",
            "dims": 1536,
            "fields": ["$"]
        }
    }
}
```
有关更多详细信息和配置选项，请参阅部署指南。

## 建立一个定制store
要使用内置实现之外的存储后端，请子类化BaseStore并实现其所需的方法。内置的InMemoryStore是最简单的参考实现。

### 基础合同
所有五个异步方法都是必需的。同步对应项(put、get、delete、search、list_namespaces)是可选的，但建议与同步图执行兼容。

| 方法 |描述 |
|---|---|
| aput(namespace, key, value, index=None) |  存储或覆盖单个项目   |
| aget(namespace, key)                    |  按键检索单个项目；如果丢失，则返回None  |
| adelete(namespace, key)                 |  删除单个项目    |
| asearch(namespace_prefix, *, query=None, filter=None, limit=10, offset=0)   |  在名称空间前缀下搜索项目；可选择通过语义查询  |
| alist_namespaces(*, prefix=None, suffix=None, max_depth=None, limit=100, offset=0) |  列出与前缀/后缀模式匹配的命名空间   |

在实施之前查找确切的签名：
```python
import inspect
from langgraph.store.base import BaseStore
print(inspect.getsource(BaseStore))
```

### 命名空间设计
命名空间是字符串的元组，例如(“user_id”，“memories”)。store实现必须支持：
- 前缀匹配：`asearch((“alice”，))`返回`(“alices”，)`、`(“alices”，“memories”)`和任何其他子命名空间下的项。
- 精确的密钥查找：`aget((“alice”，“memories”)，“some key”)`必须是O（1）或接近它。

对于SQL后端，一个常见的schema是：
```python
CREATE TABLE store_items (
    namespace   TEXT[] NOT NULL,
    key         TEXT NOT NULL,
    value       JSONB NOT NULL,
    created_at  TIMESTAMPTZ DEFAULT now(),
    updated_at  TIMESTAMPTZ DEFAULT now(),
    PRIMARY KEY (namespace, key)
);

CREATE INDEX ON store_items USING gin(namespace);
```

### 序列化
存储值是普通的Python字典——不需要特殊的序列化器。直接使用`json.dump/json.loads`或`JSONB`列进行序列化。不要存储不可JSON序列化的原始Python对象。

### 语义搜索支持
如果你的后端支持向量搜索，请在`asearch`上实现查询参数：
- 接受query：str|None参数。
- 当query不是None时，嵌入它并按余弦相似度对结果进行排名。
- 提供query时，结果应包括每个项目的score字段。

如果你的后端不支持向量搜索，请在传递query时引发`NotImplementedError`。

### 测试
目前没有自定义store的一致性套件。以InMemoryStore为参考进行测试：
```python
import pytest
from langgraph.store.memory import InMemoryStore
from your_module import YourStore

@pytest.fixture
async def store():
    async with YourStore.create() as s:
        yield s

@pytest.fixture
def reference():
    return InMemoryStore()

async def test_put_and_get(store, reference):
    ns = ("test", "ns")
    for s in [store, reference]:
        await s.aput(ns, "k1", {"val": 1})
        item = await s.aget(ns, "k1")
        assert item is not None
        assert item.value == {"val": 1}

async def test_delete(store, reference):
    ns = ("test", "ns")
    for s in [store, reference]:
        await s.aput(ns, "k1", {"val": 1})
        await s.adelete(ns, "k1")
        assert await s.aget(ns, "k1") is None

async def test_search_prefix(store, reference):
    for s in [store, reference]:
        await s.aput(("user", "memories"), "m1", {"text": "likes pizza"})
        results = await s.asearch(("user",))
        assert any(r.key == "m1" for r in results)
```
